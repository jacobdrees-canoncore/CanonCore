# Plex is reverse engineered once, into public notes

CanonCore studies Plex once, across its whole surface, with REA (morluto/rea, npm `rea-agents`): Plex Media Server observed from outside and taken apart, Plex Web, the Plex desktop app and Plex HTPC, and Plex's iOS and tvOS builds, which Extractor acquires (it gains tvOS for this). (Amended 6 Nov 2026, the Owner: Plex's iOS and tvOS code is Hermes bytecode, which REA does not read. Extractor's REA spec adds a `hermes` Stage to decode it, with hermes-decomp pinned by sha256 and hermes-dec as a separate-process fallback, and a value that bears weight, such as a spring, is checked against the disassembly. Plex's mobile code is useful for values.) The findings are public, dated notes in `docs/research/plex/`, one per part of Plex and an index, each giving the Plex version, the date and REA's evidence, and describing behaviour only: no decompiled code and no file of Plex's enters this repository, and the sweep's captures, analysis projects and extracted files are pushed to no branch (ADR 0022). Plex permitted the Owner to do this, publishing included (the Owner, 11 Oct 2026). The sweep is its own spec in Design references and runs beside the current spec, the one exception to one spec at a time (amended 31 Oct 2026, the Owner: the sweep is the first spec in Design references' order, no longer beside it; amended 2 Nov 2026, the Owner: the sweep leaves the order and closes on its merged notes, see Consequences). This is because the ADRs and specs rest on dozens of claims about Plex (19 sentences in the ADRs alone, counted 11 Oct 2026) that were read from its support pages or through search snippets, or ruled undocumented, such as its file hash (ADR 0015), and a sweep can settle them from what Plex actually does. Every ADR sentence the notes contradict goes to the Owner, and a change the Owner accepts is traced (`tracing-a-decision`); the sweep itself changes no ADR. Decided by the Owner on 11 Oct 2026.

## Considered Options

- REA on Jellyfin too: rejected, because Jellyfin is open source and is read from its source, as ADR 0013 already does.
- REA installed as an MCP server for every agent: rejected for `npx` when a ticket needs it, since the need was one sweep and REA ships several releases a week (6.2.0 to 6.4.0 between 9 and 11 Oct 2026). (Amended 2 Nov 2026, the Owner: REA is reinstated for Extractor. Amended 6 Nov 2026, the Owner, superseding "whose own spec makes REA's Ghidra snapshots and JavaScript recovery Extractor Stages": REA snapshots are not a Stage. Extractor's Decompile Stage keeps each Build's analysed Ghidra project, and Extractor's REA spec adds a `javascript` Stage, REA's application analysis of JavaScript bundles, and a `hermes` Stage, which does not use REA. Extractor installs REA as `rea-agents` 6.8.0 at an exact pin and calls it through its pinned Node by path; REA no longer runs through `npx`, here or anywhere. REA's MCP returns at user scope, on Extractor's pinned REA, with the REA spec's last ticket, which partly reverses the rejection of an MCP server. Extractor's new ADRs, on REA and its Stages and on its store on Whatbox, hold the details.)
- Notes in a private repository, as the design references are (ADR 0022): rejected, because the notes carry behaviour in CanonCore's words, not Plex's code or files, and ADRs and specs must be able to cite them.
- Only the questions CanonCore's ADRs and specs already ask: rejected for Plex's whole surface, so behaviour CanonCore has not yet considered is found too.
- Plex's Android app: dropped, as furthest from CanonCore's clients (Apple and web).
- Running Plex's apps on the iPhone and Apple TV: rejected for the builds alone, because the server sees every request the apps make, and the phone stays with the Design references specs' order.

## Consequences

- Plex becomes input to the Apple prototype (CC-39), beside Apple's TV app (`docs/design/apple-sample-code.md`, amended). Amended 2 Nov 2026, the Owner: CC-39 also captures Apple's TV app and the Infuse, Channels and Plex tvOS apps on the Owner's Apple TV through Xcode 27's Device Hub.
- The sweep's audit (CC-294) is canceled (the Owner, 2 Nov 2026), a one-off exception to "every spec ends with an audit ticket": the sweep (CC-285) closes on its merged notes, and EXT-54's complete Extractor and REA pass of every Plex target is the fresh evidence. (Note, 6 Nov 2026: that pass came before Extractor's `hermes` Stage, so it holds no decoded Plex JavaScript; that arrives when the REA spec's `hermes` Stage runs on Plex's iOS and tvOS Builds.)
- Observing Plex's API is not a step towards Plex compatibility: ADR 0009's rejection of a competitor's API stands.
- Each research note marks a claim's evidence (observed, disassembled or documented), so a note can own a claim about Plex's behaviour where Plex documents none.
