# Plex for iOS and Apple TV

## 2. What the apps are built with

Both apps are **React Native** apps, not native Swift or SwiftUI screens and not a web view. They are one code base (`react-native-client`, apps `apps/plex`, per the build paths compiled into the binaries) with a native player written in Swift.

- **observed**: each bundle has `main.jsbundle` (21 MB), which `file` identifies as "Hermes JavaScript bytecode, version 96", and `hermesvm.framework` (`dev.hermesengine.appletvos` on Apple TV). Info.plist sets `RCTNewArchEnabled` (React Native's new architecture). Each bundle's `modules.json` lists the JavaScript packages: `react-native-tvos` 0.83.10-0 (the TV fork of React Native, used for iOS too), React 19.2.4, `@react-navigation/native` 7.3.18, `react-native-screens` 4.25.2, `@tanstack/react-query` 5.102.8 with its persister, `zustand`, `@shopify/flash-list` and `@legendapp/list`, `react-native-reanimated` 4.6.0, `@op-engineering/op-sqlite` 17.0.0 with `drizzle-orm` 0.45.1, `react-native-keychain`, `react-native-udp` and `react-native-tcp-socket`, `@sentry/react-native`, `@statsig/react-native-bindings`, `react-native-iap`, Sign in with Apple and Google sign-in. The iOS bundle adds `react-native-bottom-tabs` (a native tab bar), `@gorhom/bottom-sheet`, FullStory, `react-native-inappbrowser-reborn` and Vizbee's sender SDKs; the Apple TV bundle adds only an image manipulator.
- **observed** (`otool -L`): the main executables link UIKit, SwiftUI (through a few native views), AVFoundation, AVKit, VideoToolbox, Metal and MetalKit, MediaPlayer and the Swift runtime; the Apple TV one also links TVServices. Bundled frameworks: Google IMA (ads), Kochava (attribution) and Hermes in both; iOS adds GoogleCast, FullStory and Vizbee. Neither links TVUIKit or TVMLKit.
- **observed** (REA `decode-interface-builder`): the only storyboards are the launch screens and those inside GoogleCast and Vizbee. No Plex screen is laid out in Interface Builder.
- **How the JavaScript was read.** REA 6.7.0 has no Hermes provider: `analyze-javascript-application` and the Apple graph do not open Hermes bytecode. The bytecode's string table was therefore read with a short script in scratch that follows the file header (function, string-kind and identifier counts, then the small and overflow string tables and the string storage) and prints each string. It decodes no code. It gave 115,341 strings for iOS and 115,170 for Apple TV. The strings include component and screen names, log messages, route paths, header names and the English text and descriptions of the UI messages, but **not the logic that joins them**, so behaviour read from them is marked observed and is stated as what the app contains, not the order in which it acts.
- **observed**: the two bundles hold almost the same strings: the same screen components, settings and endpoints. The Apple TV build has 20 screen components the iOS build lacks (among them a TV consent onboarding screen and a subtitle search screen), and a TV switch-user screen (`SwitchUserScreenTV`), partly because it is one release newer. So a string's presence does not show which platform uses it; where this note says something is TV-only, a TV-only string or native piece shows it.

## 3. Screens and navigation

### Screens

- **observed**: the iOS bundle names 247 screen components and the Apple TV bundle 252. Grouped: sign-in and onboarding; Home; Libraries (all libraries, a library's Recommended and browse views, Film, Show, Season and Episode pages, Collection, Playlist, Album and Artist, unmatched files, credits); Live TV (guide, channels, favourites, DVR schedule and priorities); On Demand and rentals (Plex's free and paid catalogue); Discover (trending, people, categories, decades, awards, friends' activity); Watchlist and lists; Search; Downloads (queue, completed, settings); the player and its menus (quality, audio, subtitles, speed, sleep timer, display mode); the account (profile, history, ratings and reviews, friends, privacy, notifications); server tools for the Admin (server dashboard, charts, history, Fix Match, Edit Metadata, Edit Artwork); and Settings, with a Plex Home section.
- **observed**: most screens are **laid out by Plex's servers**, not by the app. A screen family named `Luma` (`LumaListScreen`, `LumaDetailsScreen`, `LumaCustomScreen`, hero, shelves, cards) fetches its layout from `https://luma.plex.tv` (`/api/screen…`, `/api/navigation`, `/api/fragment`), sending headers `X-Plex-Luma-Version`, `-Layout`, `-Capabilities`, `-Settings`, `-Opt-Outs` and `-User-Info`. The layout header takes `tv`, `mobile` or `tablet`. So the same app shows a TV, phone or tablet arrangement of a screen as the service describes it, and the list of navigation destinations comes from `/api/navigation`.
- **observed**: the destinations the navigation can show (their message descriptions): Home, Live TV ("What's on"), On Demand (free to watch, categories, rentals), Discover, Watchlist and lists, My Libraries, Search, Downloads, Settings, the account, Sign in or Sign out, and **Switch User**.

### Home

- **observed**: Home (`HomeScreen`, titled "Home") is a Luma screen with a **hero** at the top (`LumaScreenHero`, a TV variant `LumaHeroTV` with its own buttons and an overflow menu) followed by shelves. Continue Watching is built by the app across every server the Account can reach and Plex's online sources (`mergeAndSortContinueWatching`, `continueWatchingServers`, hub identifiers `home.continue` and `home.ondeck`), with "remove from Continue Watching" (`/actions/removeFromContinueWatching`). On the TV a focused tile can play an inline preview (`FocusedTilePreview`, `autoPreviewFocused`).
- **observed**: the Apple TV Top Shelf extension fetches `https://luma.plex.tv/api/screen/continue-watching` with the Account's token, read from the keychain group it shares with the app, and shows it as sectioned Top Shelf content (`TVTopShelfSectionedContent`). It also reads the home screen's sections (`LumaHomeScreenFetcher`).
- **documented**: "Front and center features, no hidden hamburger menus"; "Dedicated Watchlist positioning in the top navigation"; "Centralized media libraries in a dedicated tab", with favourite libraries ([Release Notes for Plex Experience Preview (Apple TV)](https://forums.plex.tv/t/release-notes-for-plex-experience-preview-apple-tv/903004), post 1, Plex staff, 21 Jan 2025, describing the redesign that became this app).
- **For CC-39 story 37** (the most familiar screen judged against Plex): Plex's Home on both iOS and Apple TV is a hero over horizontal shelves, opened by a cross-server Continue Watching shelf and mixed with Plex's own online catalogue (On Demand, Discover, Live TV), not a library of the Admin's files. The order and the shelves are chosen by Plex's service per layout (`tv`, `mobile`, `tablet`), so the bundle cannot say which shelves a given Account sees, or in what order. Apple's TV app stays the reference; Plex's Home is the counter-example of a home screen built from a server-chosen mix.

### Navigation

- **iOS: a native tab bar. observed**: the iOS bundle alone carries `react-native-bottom-tabs` and its native view (`RNCTabView`, `TabViewProvider`, 26 and 7 strings in the executable), and imports `UITabBarController` and `UITab`, the iOS 18 tab API that becomes a sidebar on iPad. Screens push onto native stacks (`RNSScreenStack`). **documented**: the older mobile apps opened a navigation drawer from a ☰ button ([Fast User Switching](https://support.plex.tv/articles/204232453-fast-user-switching/), last modified 19 Nov 2023); this build has a tab bar instead.
- **Apple TV: a sidebar drawer. observed**: the Apple TV build lacks the native tab package (no `TabViewProvider`) and uses a drawer navigator (`createDrawerNavigator`, `focusDrawer`, `handleDrawerFocus`, `sidebar-collapse` and `sidebar-expand`, `SidebarIndicator`). The drawer has a section of Plex-wide destinations, a section of promoted libraries and an item that opens all libraries ("Drawer nav: …" descriptions). A What's New card announces "Improved Sidebar": "Get where you want to go faster with a more organized sidebar", fetched from `/api/screen/whats-new/side-nav`. Within a screen, a row of top pivots remains (**documented**: "focus jumping to the top navigation when changing a filter or sort on a Library Browse screen", 2026.11.0, [release notes](https://forums.plex.tv/t/release-notes-for-plex-experience-preview-apple-tv/903004), post 22, 8 Jun 2026). The January 2025 preview put the Watchlist in a top bar (post 1); this build's sidebar replaced that bar as the main navigation.
- **observed**: deep links use the `plex://` scheme and universal links on `watch.plex.tv`, `l.plex.tv`, `plex.smart.link` (both) and `links.plex.tv` and `click.plex.tv` (iOS) (entitlements). The app's own routes are path-like (`/home`, `/libraries`, `/live-tv/guide`, `/watchlist`, `/account/switch-user`, `/downloads`, `/settings/plexHome`, `/watch/video`).

### Focus on Apple TV

- **observed**: focus runs through React Native tvOS's focus support, which sits on UIKit's focus engine: the executable imports `UIFocusGuide`, `UIFocusSystem` and `UIFocusUpdateContext`, and the JavaScript uses `TVFocusGuideView`, `hasTVPreferredFocus`, `nextFocusUp`/`Down`/`Left`/`Right`, `trapFocusUp`/`Down`/`Left`/`Right`, `autoFocus` and `destinations`. On top of that Plex has its own focus layer: focus groups per screen (`FocusGroup`, `CurrentScreenFocusGroupProvider`), an "initial focus" priority each screen's hero, actions, lists and sections can claim (`addInitialFocusPriorityToScreenHero`, `claimInitialFocus`), remembered focus per row and per screen (`getRememberedFocusIndex`, `useRestoreFocusOnReturn`, `FocusRetainer`, `RefocusGroup`) and a handler for lost focus (`FocusLostHandler`).
- **observed**: a user setting, "Always Focus Initial Element": "When navigating to a new screen, always focus the initial focus element. If disabled, the initial focus element will only be focused the first time you visit a screen." So by default returning to a screen restores where focus was.
- **observed**: shelves keep focus on their row and snap the focused section (`keepFocusOnRow`, `keepFocusedSectionSnapped`, `alignFocusedIndex`, `focusAdjacentRow`); focused tiles scale (`scaleOnFocus`) and some use the parallax style (`tvParallaxProperties`); a carousel has its own focus controls (`TVCarouselFocusControls`). The Live TV guide debounces focus changes ("Debounce time for focus changes in the Live TV guide").
- **observed**: the remote's buttons reach JavaScript through `TVEventHandler` (`longSelect`, `playPause`, the menu key through `TVEventControl.enableTVMenuKey`). A long press opens a context menu on items (`onItemLongPress`, `useOpenContextMenu`, `ListContextMenuActionsScreen`), and long-press actions exist for libraries in the sidebar (`handleDrawerItemLongPress`, `libraryLongPressAction`) and for activity cards. Play/Pause on a focused tile is handled (`FocusedTilePlayPauseHandler`).
- **documented**: Plex's release notes record focus fixes of exactly these kinds, such as "User switcher now focuses the current user instead of the first user in the list" and "Wrong initial focus on Play History screen" (2026.8.0 and 2026.11.0, [release notes](https://forums.plex.tv/t/release-notes-for-plex-experience-preview-apple-tv/903004), posts 21 and 22).

## 4. The profile picker, and following the device's user

### Plex's own picker

- **observed**: both apps have a switch-user screen titled "Who's watching?" (`SwitchUserScreenContent`; the Apple TV build adds `SwitchUserScreenTV` and a command palette action "switch user"). It lists the Plex Home's users from plex.tv (`/api/home/users`, `/api/v2/home/users/`) and switches with `/api/v2/home/users/{uuid}/switch` (route `/switch`). A protected user asks for a PIN ("Enter PIN", "Incorrect PIN. Try Again.", accessibility messages for an empty, entered or wrong PIN). Managing the Home from the picker needs the Admin's PIN ("The admin PIN is required to manage Plex Home"; "Select to sign in as the admin and manage Plex Home"). Switch User is also a navigation destination.
- **observed**: a setting "Automatically Sign In" (`automaticallySignIn`). **documented**: "In the General Settings of Plex Player apps full regular accounts can choose to skip pin entry and automatically sign into the last used Home account for any given app. It will not prompt to select a user or enter a PIN during startup on this device", and a PIN is asked when "you launch a supported app that was previously last signed in to a protected user" ([Fast User Switching](https://support.plex.tv/articles/204232453-fast-user-switching/), last modified 19 Nov 2023). **documented**: "Signing in as a Home Admin was redirecting to Home instead of the Switch User screen" was fixed (2025, [release notes](https://forums.plex.tv/t/release-notes-for-plex-experience-preview-apple-tv/903004), post 15), so after sign-in a Home's Admin lands on the picker.
- **observed**: downloads are kept per Plex user (`userUuid` on the local `downloads` table, `clearDownloadsForPreviousUsers`).

### Following the Apple TV's user

- **observed**: the Apple TV app's entitlements have **no** `com.apple.developer.user-management` entry (only application identifier, push, Sign in with Apple, associated domains, app groups `group.com.plexapp.shared` and `group.com.plexapp.plex.topshelf`, keychain groups, and `com.apple.smoot.subscriptionservice`, the video-partner entitlement for Apple's TV app). Neither the app nor its Top Shelf extension imports `TVUserManager` or any TVServices user API (`nm -u`: the only TVServices classes are the Top Shelf ones), and no string names `currentUserIdentifier`, `runs-as-current-user` or a tvOS user change.
- **documented** (Apple): an app opts in to separate data per Apple TV user by adding the User Management entitlement; without it the app keeps single-user behaviour, one set of data for everyone on the Apple TV ([Mapping Apple TV users to app profiles](https://developer.apple.com/documentation/tvservices/mapping-apple-tv-users-to-app-profiles), read through Apple's documentation JSON on 18 Oct 2026; [User Management Entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.user-management)).
- So Plex for Apple TV is signed in once per Apple TV, shares one set of data across the Apple TV's users, and chooses who is watching with its own picker, optionally skipped by "Automatically Sign In" to the last-used Home user. It does not map the tvOS user to a Plex Home user. The iOS app, on a single-user device, has the same picker.

## 5. The playback stack

### Three engines

- **observed** (build paths and class names in the executables): the native player package (`packages/player/ios`, Swift module `plex_react_native_video`) carries:
  1. **AVPlayer** (`avplayer/Player.swift`), Apple's player, with an **AVPlayer proxy** (`AVPlayerProxy`, a local HTTP server, `APHTTPServer`) that serves the stream to AVPlayer from loopback; "AVPlayerProxy could not start, loading directly" shows it falls back to a direct URL. A testing setting, "Force AVPlayer Proxy", reads "Serve playback through the local proxy even when the server is reachable directly. For testing the proxy path." Both apps.
  2. **Plex's private fork of KSPlayer** (`KSPlayer_private`), a Swift player on FFmpeg, with its two engines: `KSAVPlayer` (on AVPlayer) and `KSMEPlayer` (FFmpeg demux and decode, VideoToolbox hardware decode, Metal rendering in `MetalPlayView`, its own audio renderers, libass for subtitles). Both apps. `KSPlayerVideoPlayer` is Plex's wrapper.
  3. **A newer engine, Apple TV only** (`applayer`, `APEngine`, `NativeEngineManagerNext`, and in the fork `APPlayer`, with an FFmpeg demuxer named `ffplex`, a VideoToolbox video decoder, an HLS demuxer and live-playlist controller, AVSampleBuffer renderers and a playback state machine). The Apple TV app has a user setting **"Experimental Player Engine"** (`experimentalPlayerEngine`), with `experimentalDolbyVisionSupport` and `isForcingDoViProfile7` passed to the native side, and the native log line "Selected engine: ". The iOS build has none of these.
- **observed**: FFmpeg is linked statically (FFmpegKit, `PodsDummy_FFmpegKit_tvOS`) with dav1d for AV1 and libass, and its decoder table includes H.264, HEVC, AV1, VP9, VC-1, MPEG-2, MPEG-4 part 2 and WMV; AC-3, E-AC-3, DTS and DTS-HD, TrueHD and MLP, FLAC and Opus; PGS, DVD (VobSub), ASS, SRT and WebVTT subtitles; and Matroska, MP4/MOV, MPEG-TS and AVI demuxers. The Apple TV build adds Dolby Vision and HDR10+ handling around VideoToolbox (stripping Dolby Vision or HDR10+ data from a bitstream, a Dolby Vision profile 5 check, a TrueHD filter) and sets the display's frame rate and dynamic range (`AVDisplayCriteria`, imported; `DisplayCriteria.swift`).
- **disassembled** (REA `search --kind procedures` and `function` with Ghidra on the Apple TV executable; Objective-C and Swift class names survive, other functions are named by address): the player module has three engine classes, `AVPlayerEngine`, `KSPlayerEngine` and `APEngine`, and two managers, the older `NativeEngineManagerImpl` and `NativeEngineManagerNextImpl`, chosen by a `usesNextEngineManager` flag in the load configuration. The next manager's load (the body at `0x100d08174`) reads the item's flags from the configuration (from Plex's online catalogue, a FAST channel, live, Dolby Vision profile 5, theme music) and the two experimental settings, then picks an engine:
  - **KSPlayer's FFmpeg engine** is the default for the Admin's and shared media;
  - **AVPlayer** instead when the item is live or Dolby Vision profile 5 and the experimental engine is off, and always when the item comes from Plex's online catalogue, is a FAST channel, the Apple TV is sending to AirPlay, or the device fails a model check (a value from a device lookup must exceed 5; which Apple TV models pass was not traced);
  - **the new engine** (`APEngine`) when "Experimental Player Engine" is on, subject to the same catalogue, FAST, AirPlay and model exceptions.
  REA's `trace` of the "Selected engine: " string found the string but no reference to it, because Swift addresses string literals indirectly; the procedure search was used instead.
- **documented**: a Plex employee's beta thread for the Apple TV player says the work targets "high bitrate HDR content" and renders "on Metal" ([Apple Player Update Beta Testing](https://forums.plex.tv/t/apple-player-update-beta-testing/872121), post 1, 14 Mar 2024).

### What each decides to play itself

- **observed**: the decision is made in the app first, by a JavaScript `MediaDecisionEngine` that logs "Direct play is supported for this media item", "Direct stream is supported for this media item" or "Transcoding is required for this media item", and "Playing video as …", "Playing audio as …", "Subtitles as …". It asks the native side what the device decodes, codec by codec: `isVideoSupported(codec, profile, level, bitrate, frame rate, height, width, bit depth)` and `isAudioSupported(codec, profile, bitrate, channels, sample rate, passthrough)` ("[Capabilities] …" log lines), both apps. **disassembled** (Apple TV, `NativeCapabilitiesImpl` `isVideoSupportedWithCodecName…` at `0x100cf1940`): the video answer is yes for every codec except Dolby Vision, which is decided from the device; the profile, level, bitrate, frame rate and size passed in are not consulted there. So the device declares it can play any video codec, which matches the FFmpeg engine being the default. The audio probe's bridge (`0x100cb4b04`) forwards to code Ghidra did not resolve, and its rules were not read. It then builds a client profile sent as `X-Plex-Client-Profile-Name` and `X-Plex-Client-Profile-Extra` with `add-direct-play-profile`, `add-transcode-target`, `add-transcode-target-codec`, `append-transcode-target-codec`, `add-transcode-target-settings` and `add-limitation`, and asks the server (`/video/:/transcode/universal/decision`, `/music/:/transcode/universal/decision`). Transcode starts are `start.m3u8` (HLS), `start.mpd` (DASH) and `start.mkv`.
- **observed**: the server transcode is a fallback after a failed direct play: "[TranscodeFallbackInterceptor] Error occurred whilst direct playing, reloading as a transcode." Other reloads happen when the quality, speed, subtitle sync, dialogue boost or loudness setting changes, and when the connection moves from Wi-Fi to cellular. Live TV audio is limited to what AVPlayer plays ("Restricting Live TV audio transcode to AVPlayer supported codecs"); **documented**: Live TV is restricted "to transcode to h264 for better playback compatibility" (release notes, post 13, 26 May 2025).
- **observed**: settings `allowDirectPlay`, `allowDirectStream` and `forceDirectPlay`, and `preferDirectPlay`, `preferDirectStreamAudio` and `preferDirectStreamVideo`.
- **Not settled**: the exact codec lists each app declares, because they are built at run time from the native answers and the code that assembles them is Hermes bytecode, which REA does not decode. Which profile name each sends is also not settled: the strings include `Generic`, "Plex for iOS" and "Plex for Apple TV" without the code that chooses.

### Verdicts on the playback claims

- **ADR 0010, "Their own first-party apps also decode on the device (Swiftfin with VLCKit, Plex HTPC with mpv)"**: **confirmed, and Plex's Apple apps do too**. HTPC with mpv is confirmed in [`desktop-and-htpc.md`](desktop-and-htpc.md). Plex's iOS and Apple TV apps bundle FFmpeg (through Plex's KSPlayer fork) with VC-1, MPEG-2, VP9, AV1, TrueHD, DTS and PGS/VobSub decoders and a Metal renderer, besides AVPlayer, and probe the device per codec before choosing direct play (observed). On the Apple TV the FFmpeg engine is the default for the Admin's media, with AVPlayer kept for Plex's online catalogue, FAST channels, AirPlay and some live and Dolby Vision items (disassembled). The sentence could name them: on Apple devices Plex's own decoder is FFmpeg in a KSPlayer fork, not mpv or VLCKit.
- **ADR 0010, "Server transcoding as the fallback every client leans on, as Plex, Jellyfin and Emby's web and many TV clients do"**: **contradicted for Plex's Apple apps**. They decide direct play on the device from measured capabilities and decode most formats themselves; the server transcode is a fallback after a direct play error, a quality cap or Live TV (observed). The sentence still holds for Plex Web ([`web.md`](web.md)).
- **CC-11, "Plex uses server transcoding as the fallback"**: **confirmed** in that sense: the apps reload as a transcode when direct play fails (observed).
- **CC-11, "Plex HTPC with mpv"**: **confirmed**, by [`desktop-and-htpc.md`](desktop-and-htpc.md) (observed and documented there).

## 6. How the apps reach the server and plex.tv

Cross-referenced to [`server-api.md`](server-api.md) by section.

- **Sign-in. observed**: the Apple TV app's sign-in shows a code and a QR code ("Visit this link in your browser or scan the QR code with your phone", "Visit this link in your browser and enter the code below"), from plex.tv PINs (`/api/v2/pins?strong=`, `/api/v2/pins/{id}`, `/api/v2/pins/link`), with `https://app.plex.tv/auth/` for the strong form. Sign in with Apple, Google and Amazon are offered beside the code ("OR text between pin code and federated auth sign in"), and the token is checked and refreshed with `/api/v2/users/authenticate`, `/api/v2/users/validate` and `/api/v2/user`; `/api/v2/users/anonymous` lets someone use Plex's free catalogue unsigned. The iOS app has no password form of its own: it opens Plex's web sign-in (`https://app.plex.tv/auth/` with a `forwardUrl`) in a system authentication session (`InAppBrowser.openAuth`, importing `ASWebAuthenticationSession` and `SFSafariViewController`), beside native Sign in with Apple (`ASAuthorizationAppleIDProvider`) and Google. **documented**: big-screen apps show "a 4-character code", optionally a QR code; the user enters it at plex.tv/link "and ensure that you're signed into the appropriate Plex account", and "your player app will refresh itself a few seconds later" ([Connect App to Your Plex Account](https://support.plex.tv/articles/203395277-connect-app-to-your-plex-account/), last modified 7 Jul 2025). This is the PIN flow of server-api.md, "Users: server-side accounts, and plex.tv" (plex.tv table) and "Tokens", item 2.
- **Profile switching**: `/api/home/users`, `/api/v2/home/users/` and the switch call, as in server-api.md, "Users …" (plex.tv table).
- **Finding servers. observed**: the server list comes from plex.tv's resources (`/resources` with `includeHttps` and `includeRelay`), and each server's connections are tested and the best kept ("[Connections] Testing …", "Best connection to …"); relay connections are known (`relay`). On the local network the apps also send GDM queries (`M-SEARCH * HTTP/1.1` to `239.0.0.250` and by broadcast, through `react-native-udp`). The native side guards `*.plex.direct` names against DNS rebinding protection (`DNSRebindingProtectionUrlProtocol`). iOS declares the local network use (`NSLocalNetworkUsageDescription`, Bonjour `_plexapi._tcp`, the multicast entitlement). See server-api.md, "How to reach this server" and the resources row.
- **Being a remote-controllable player. observed**: the apps answer GDM queries as a player (`plex/media-player`, `Resource-Identifier`, `Device-Class`, `Protocol-Capabilities`; "[GDM] Sending a 200 OK for an M-SEARCH") and run a local companion HTTP server ("[Companion HTTP] Listening on port …", `react-native-tcp-socket`) that takes `/player/playback/*` commands and timeline subscriptions; they can also control other players (`/player/timeline/poll`, `/player/playback/playMedia`). - **Server endpoints. observed**: library and metadata (`/library/sections`, `/library/metadata/…`, `/library/all`, `/hubs/metadata/…`, `/library/search`), play queues, timeline (`/:/timeline`), scrobble and rate, transcode decision and start, `/photo/:/transcode`, `/media/providers`, `/media/subscriptions` (Downloads), `/status/sessions` and `/statistics/*` (the Admin's dashboard) and the server's websocket `/:/websockets/notifications`; plus Plex's online services (`discover.provider.plex.tv`, `vod.provider.plex.tv`, `epg.provider.plex.tv`, `luma.plex.tv`, `pubsub.plex.tv`, `together.plex.tv`, `features.plex.tv`). See server-api.md, "Endpoints". The Top Shelf extension carries a pattern that masks an `X-Plex-Token=` query value, which suggests it logs URLs carrying the token in the query; this was not traced.

### Fetching per screen

- **observed**: neither app keeps a copy of the Library. Its SQLite database (op-sqlite and drizzle) has tables for Downloads only (`downloads`, `media_server_queues`, `metadata` for downloaded Items, `playback_metadata` with `viewOffset` per download, `state`) and a key-value `storage` table. Screens load their data when they open, through React Query, with paging headers; a refresh rule per Luma screen ("[LumaScreen] Refreshing all data for screen"). The query cache is persisted (`PersistQueryClientProvider`, `createAsyncStoragePersister`), so the last answers for a screen can be shown again at launch; which queries are persisted was not settled.
- **ADR 0014, "Fetching per screen, as Plex and Jellyfin do"**: **confirmed for Plex's Apple apps**, with the note that they persist screen responses as a cache.

## 8. What could not be settled, and why

- **The order of anything in the JavaScript**: when the picker appears at launch, how "Automatically Sign In" is stored (on the device or on the Account), which codecs each app declares, which profile name it sends, and which queries are persisted. The logic is Hermes bytecode; REA 6.7.0 has no Hermes provider, and this ticket read only its string table.
- **Which shelves Home shows and in what order**, and which destinations the sidebar and tab bar list: both come from `luma.plex.tv` at run time, per Account and layout, and no request was made.
- **How often each app transcodes in practice**, and how the iOS app chooses between AVPlayer and KSPlayer: no app was run against a server, and only the Apple TV executable was disassembled (each Ghidra query on its 43 MB executable took ten to thirty minutes). On the Apple TV, when the older engine manager is used instead of the next one, and which Apple TV models fail the model check, were not traced either.
- **The audio capability rules**, such as which Apple TVs pass TrueHD or DTS through: the audio probe's body was not resolved by Ghidra.
- **What the Apple TV sidebar looks like collapsed and expanded**, and the remote's exact long-press bindings: no screenshot or run was allowed, and the strings name behaviours, not layouts.
- **Whether `/api/v2/pins/link` is the phone side of the code flow** (an iOS app entering a TV's code): only the path is seen.
