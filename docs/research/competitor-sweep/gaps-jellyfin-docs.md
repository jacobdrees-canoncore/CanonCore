# Jellyfin documentation sweep — feature inventory and CanonCore gaps

STATUS: complete

Sweep of https://jellyfin.org/docs/ against `prompt.md`.
Every feature is rated against the CanonCore prompt:

- **ADOPTED** — the prompt does the same thing.
- **REFUSED** — the prompt explicitly rules it out (WHAT NOT TO BUILD / STANDING RULES).
- **DIVERGENT** — the prompt deliberately does something different.
- **ABSENT** — the prompt says nothing at all. Rated LOW / MEDIUM / HIGH for whether a
  self-hosted media catalogue genuinely needs it.

## 1. Libraries, library types and on-disk media layout

Sources: <https://jellyfin.org/docs/general/server/libraries>,
`/docs/general/server/media/movies`, `/shows`, `/music`, `/books`, `/music-videos`,
`/placeholders`, `/excluding-directory`, `/mixed-movies-and-shows`.

| # | Jellyfin feature | One line | CanonCore |
|---|---|---|---|
| 1.1 | **Library = virtual collection over several paths** ([libraries](https://jellyfin.org/docs/general/server/libraries)) | A library maps N filesystem paths into one browsable unit. | **ADOPTED (partial)** — prompt's `groups` scope "scanner roots"; multi-root per group is implied but never stated. |
| 1.2 | **Library content type is typed** (movies / shows / music / books / photos / mixed) | The type selects the scanner, the metadata providers and the client layout. | **REFUSED** — "WHY never typed by medium: a Plex library is typed, and that is exactly what stops a container holding mixed media." |
| 1.3 | **Mixed library type "is broken and deprecated"** ([mixed](https://jellyfin.org/docs/general/server/media/mixed-movies-and-shows)) | Jellyfin's own docs disown the untyped library. Whole page is two sentences. | Evidence *for* CanonCore's refusal of typing: Jellyfin's untyped path is the one it could not make work. |
| 1.4 | **`.ignore` files exclude dirs/files from scans** ([excluding-directory](https://jellyfin.org/docs/general/server/media/excluding-directory)) | Empty `.ignore` skips a whole dir; non-empty is `.gitignore` pattern syntax (10.11+). | **ABSENT — MEDIUM/HIGH.** Every real library has OSTs, samples, extras and work-in-progress dirs; without an exclusion mechanism the scanner ingests junk that the owner then has to delete item by item. |
| 1.5 | **Placeholders — empty `.disc` files** ([placeholders](https://jellyfin.org/docs/general/server/media/placeholders)) | An item with no playable file, created by touching `Movie (1982).disc`. | **DIVERGENT (CanonCore better)** — items are media-independent with zero files, no sentinel file needed. Confirms prompt's claim #1 is *nearly* true: Jellyfin does have file-less items, but only via a real file on disk. Worth noting the prompt's phrasing ("an item cannot exist without a file") is slightly overstated — the file is empty, but it must exist. |
| 1.6 | **Placeholder media-type vocabulary** (`dvd`, `hddvd`, `bluray`, `brrip`, `bd25`, `bd50`, `vhs`, `hdtv`, `pdtv`, `dsr`) | Physical carrier recorded as a filename token. | **DIVERGENT** — CanonCore would make this a `category` statement on an edition. No gap. |
| 1.7 | **Multiple versions in one folder via ` - Label` suffix** ([_video-multiversion](https://github.com/jellyfin/jellyfin.org/blob/master/docs/general/server/media/_video-multiversion.md)) | `Movie (2021) - Directors Cut.mp4` groups as a version of the same movie. Prefix must match char-for-char. | **DIVERGENT** — CanonCore has an `editions` table. **But see 1.8.** |
| 1.8 | **How a file binds to a version** — filename suffix, or manual "Group Versions" in the UI | Jellyfin's answer to "which version is this file" is (a) naming convention or (b) an explicit user grouping action. | **ABSENT — HIGH.** CanonCore says files attach "to item or edition" but never says how the scanner decides *which edition*. With no filename convention, no `.nfo` and no user grouping gesture specified, a two-cut film scans as two unassigned files. This is the single biggest unspecified mechanism in the scanner half. |
| 1.9 | **Version ordering rule** — alphabetical, except resolution names (ending `p`/`i`) sort descending; first in list is the default | Jellyfin's default-version pick is a sort rule. | **DIVERGENT** — prompt: `is_default` pin, else a declared edition order, never recency. Prompt's claim that Plex picks "what the client can decode" is right; Jellyfin's is a *name sort*, which is arguably worse and is not mentioned in the prompt. |
| 1.10 | **Multi-part / stacked files** (`-cd1`, `-part-1`, `pt`, `disc`, `disk`; separators space/`.`/`-`/`_`) | One logical item spanning several files, played in sequence. Explicitly incompatible with multiple versions. | **ABSENT — MEDIUM/HIGH.** CanonCore's `files` table has no ordering and no notion of one edition spanning N files; a two-disc film or a 30-file audiobook has no representation, and progress across parts is undefined. |
| 1.11 | **Multiple episodes in one file** (`S01E01-E02`) | One file resolves to several items; shown as a single entry merging both episodes' metadata. | **ABSENT — MEDIUM.** `edition_coverage` intervals could express it, but the prompt never states that one file may satisfy several items, and the two-figure rollup depends on knowing this. |
| 1.12 | **External subtitle/audio sidecars by filename suffix, with flags** ([_video-external-streams](https://github.com/jellyfin/jellyfin.org/blob/master/docs/general/server/media/_video-external-streams.md)) | `Film.en.sdh.srt`; flags `default`, `forced`/`foreign`, `sdh`/`cc`/`hi`; unparsed text becomes the stream title; `hi` collides with Hindi. | **PARTIAL.** CanonCore has file role `subtitle`/`audio` + language. **ABSENT — MEDIUM:** the flags (default / forced / hearing-impaired), the free-text track title, and the language-code collision problem. A subtitle picker cannot be built from language alone. |
| 1.13 | **Extras** — 12 folder types (`behind the scenes`, `deleted scenes`, `interviews`, `scenes`, `samples`, `shorts`, `featurettes`, `clips`, `other`, `extras`, `trailers`, `theme-music`, `backdrops`), plus `trailer`/`sample` filenames and ~16 filename suffixes | Bonus content attached to a movie/series/season without becoming a library item. | **ABSENT — MEDIUM.** CanonCore has no concept between "a file" and "an item"; a making-of is either a full `work` item polluting browse surfaces, or nothing. The prompt's own demo (Harry Potter) is exactly the kind of library that has extras. |
| 1.14 | **Theme media** — `theme.ext`, `theme-music/*`, `backdrops/*` autoplay while browsing | Ambient audio/video on library pages; video wins over song; multiples shuffle. | **ABSENT — LOW.** Cosmetic. |
| 1.15 | **3D format flags** (`3D` + `hsbs`/`fsbs`/`htab`/`ftab`/`mvc`; anaglyph unsupported) | Stereoscopic layout recorded in the filename. | **ABSENT — LOW.** |
| 1.16 | **Show specials ordering** — `Season 00` plus `airsbefore_season`, `airsafter_season`, `airsbefore_episode`; ties break by storage order ([shows](https://jellyfin.org/docs/general/server/media/shows)) | A special appears in both the Specials season and inline in the aired season. | **DIVERGENT (CanonCore better)** — this is exactly a second placement at a second position, which placements do natively. Note Jellyfin *does* let one episode appear in two orderings here, which slightly qualifies the prompt's reason #2; the mechanism is three metadata fields, not a general one. |
| 1.17 | **Season folders must be `Season NN`, zero-padded, not `S01`** | Ordering and hierarchy live in the directory names. | **REFUSED / DIVERGENT** — prompt reason #2. Confirmed by the docs. |
| 1.18 | **Music: albums identified by folder, metadata read from embedded tags** ([music](https://jellyfin.org/docs/general/server/media/music)) | "Filenames generally do not matter since the info will be scraped from the embedded metadata of the tracks." | **ABSENT — HIGH.** CanonCore never reads embedded file tags; the scanner "takes media files and playback sidecars, and nothing else", and artwork is provider-only. Consequence: a private CanonCore instance with no provider connected has *no track titles, no album, no artist, no cover* for music. That is a knowable, stated consequence for artwork; for embedded tags it is neither stated nor decided. |
| 1.19 | **Disc number / total discs from embedded tags; disc folders optional, tags win** | Multi-disc albums are one album. | **ABSENT — MEDIUM.** Follows from 1.18 and from 1.10 (part ordering). |
| 1.20 | **Lyrics sidecars** — `.lrc`, `.elrc`, `.txt`, synchronised (`[00:10.89]Line`) and click-to-seek | Timed text tied to an audio file. | **ABSENT — MEDIUM.** CanonCore's file roles are `media\|subtitle\|audio\|chapters`; lyrics have no role, and a synced-lyrics view is the main thing a music catalogue's play screen shows. |
| 1.21 | **Books need the Bookshelf plugin; online metadata unsupported for books** ([books](https://jellyfin.org/docs/general/server/media/books)) | Books are a second-class citizen; metadata comes from `content.opf` / `metadata.opf` / `ComicInfo.xml`. | **REFUSED** (no sidecar metadata reading) — but note Jellyfin has *no* online book provider at all, so CanonCore's text-medium editions are unmatched by the incumbent. |
| 1.22 | **Read-along audiobooks explicitly not supported** | Synced text+audio. | **ABSENT — LOW.** |
| 1.23 | **Image types & filenames** ([_metadata-images](https://github.com/jellyfin/jellyfin.org/blob/master/docs/general/server/media/_metadata-images.md)) | Roles: Primary, Backdrop, Banner, Logo, Thumb (+ unused Art, Disc, Box, Menu, Chapter, BoxRear, Profile, Screenshot). ~22 recognised filenames. External images take precedence over other sources. | **DIVERGENT + partial gap.** CanonCore roles are `poster\|backdrop\|title-logo\|still`. **ABSENT — MEDIUM:** `banner` and `thumb`/`landscape` are distinct aspect ratios that browse layouts need and cannot be derived from a poster. |
| 1.24 | **Multiple backdrops cycle** (`backdrop-1.jpg`, `backdrop2.jpg`) | N backdrops per item, rotated over time. | **PARTIAL** — CanonCore's artwork table is 1..n by construction, so this works; but the *palette* rule then needs a defined answer for "which of five backdrops' palette does the page use". Not stated. **ABSENT — LOW/MEDIUM.** |
| 1.25 | **Embedded Image Extractor source** — covers pulled out of mkv/flac containers | An artwork source that is not a provider. | **REFUSED** ("no artwork scanning"). Consequence accepted in the prompt. |
| 1.26 | **Reserved characters** `< > : " / \ \| ? *` break the scanner | Filename hygiene. | **ABSENT — LOW.** |
| 1.27 | **Container caveats** — audio-only `.mp4`→`.m4a`, `.mkv`/`.webm`→`.mka`, `.weba` unsupported, ID3v1 30-byte truncation, FLAC+WebP fails in Chromium | Extension-based type detection is load-bearing and lossy. | **ABSENT — MEDIUM.** A direct-play-only product inherits every one of these browser-codec failure modes, and the prompt's rule is only "when a file will not play, say so plainly" with no mechanism for knowing in advance. |
| 1.28 | **`VIDEO_TS` / `BDMV` folder support; `.iso` "should work, but are not supported"** | A single item whose media is a directory tree, with no multi-version/multi-part/external-track support. | **ABSENT — LOW/MEDIUM.** CanonCore's file identity is SHA1 over one file's bytes; a disc folder has no single file to hash. |

**Jellyfin docs thin/contradictory here:** the Libraries page is 5 paragraphs and documents none of the per-library scan settings that actually exist in the UI (see §4). `mixed-movies-and-shows` is a stub admitting the feature is broken. `_video-header` says `.iso` "should work, but are not supported" — a contradiction the docs do not resolve.

## 2. Metadata: providers, identifiers, NFO, chapters, media segments

Sources: <https://jellyfin.org/docs/general/server/metadata/>,
`/metadata/identifiers`, `/metadata/nfo`, `/metadata/chapter-images`, `/metadata/media-segments`.

| # | Jellyfin feature | One line | CanonCore |
|---|---|---|---|
| 2.1 | **Bundled providers: TMDb, OMDb, local `.nfo`**; more (TheTVDB, fanart.tv, AniDB) via plugins ([metadata](https://jellyfin.org/docs/general/server/metadata/)) | Providers ship in-process; third parties add more as plugins. | **DIVERGENT** — CanonCore ships provider *definitions* disabled by default and providers are URLs answering CMPP, never code in-process. |
| 2.2 | **OMDb is English-only**; TMDb and TheTVDB are **blocked in mainland China** | Provider availability is jurisdictional and language-limited. | **ABSENT — LOW/MEDIUM.** No provider-level language preference or per-provider availability/failure surface is specified; the prompt has provider failure *modes* in the contract test but nothing about a provider being permanently unreachable for a whole region. |
| 2.3 | **Provider IDs embedded in file/folder names**, multiple allowed: `[tmdbid-680] [imdbid-1234] [tvdbid-79168]` ([identifiers](https://jellyfin.org/docs/general/server/metadata/identifiers)) | Identity is pinned on disk so a rescan re-matches deterministically. | **ABSENT — MEDIUM/HIGH.** CanonCore stores identifiers as statements with a scheme (good), but has **no stated mechanism for a file on disk to declare which item it belongs to**. Combined with 1.8, the whole file→item binding is unspecified. Jellyfin's answer is the filename; `.nfo` is refused; nothing replaces either. |
| 2.4 | **`.nfo` read vocabulary** — ~45 tags incl. `sortname`, `sorttitle`, `originaltitle`, `localtitle`, `plot`, `tagline`, `mpaa`, `customrating`, `criticrating`, `ratings` (critic vs community), `runtime`, `aspectratio`, `studio`, `director`, `writer`, `credits`, `actor`, `genre`, `tag`, `style`, `country`, `countrycode`, `language`, `premiered`/`aired`/`releasedate`/`enddate`/`formed`, `uniqueid`, `displayorder` ([nfo](https://jellyfin.org/docs/general/server/metadata/nfo)) | The de facto field set of the whole category (shared with Kodi). | **REFUSED as a format**, but useful as a **field-set checklist**. CanonCore seeds ~a dozen properties. Fields Jellyfin has that the prompt names nowhere: `tagline`, `originaltitle`/`localtitle` (title language variants), content rating (`mpaa`/`customrating`), critic vs community `ratings`, `genre`, `country`, `studio`, `aspectratio`, `enddate`. **ABSENT — MEDIUM:** *title language variants* specifically, since the prompt makes `title` a single column and the demo (Harry Potter) has a different title in two markets. |
| 2.5 | **`lockedfields` / `lockdata`** | Per-field boolean lock, plus a whole-item lock, persisted in the NFO. | **REFUSED** — "No per-field lock flag. The favourite does that job." Confirms the prompt's claim #3: the ceiling is a boolean lock. **But note `lockdata`** — a *whole-item* "never touch this again" flag. CanonCore's favourite locks a field; there is no item-level equivalent. **ABSENT — MEDIUM.** |
| 2.6 | **`.nfo` cannot be disabled and always beats remote providers** | "It's currently not possible to disable .nfo metadata. Local metadata will always be fetched and has priority over remote metadata providers like TMDb." | Direct evidence for the prompt's "first-non-empty-wins, losing answers discarded" critique — and the source order here is hardcoded, not configurable. |
| 2.7 | **`.nfo` writing ("Nfo saver")** — Jellyfin writes metadata back to the media folders | Export path; also a filesystem write from the scanner side. | **REFUSED** — "The scanner NEVER writes storage." |
| 2.8 | **NFO user-data import is single-user only** (`watched`, `playcount`, `lastplayed`) | Progress import is limited to one nominated user. | **REFUSED** (no import). Consistent. |
| 2.9 | **"Only one image per artwork type" from NFO; NFO image paths beat both remote providers and folder images** | A third precedence tier for artwork. | Evidence that artwork precedence is a real, contested problem. CanonCore's answer (provider-only) sidesteps it. |
| 2.10 | **Chapters** — timeline ticks read from the media file ([chapter-images](https://jellyfin.org/docs/general/server/metadata/chapter-images)) | Named time points inside a file, shown on the scrubber. | **PARTIAL** — CanonCore has a `chapters` file role but never says what a chapter *is* as data, or that it is displayed. **ABSENT — MEDIUM:** chapter data model and where chapter names come from. |
| 2.11 | **Chapter image extraction** — per-library toggle; optionally during library scan; "computationally intensive and slow down library scans significantly"; configurable **resolution**; **dummy chapters at a fixed interval** when the file has none | Thumbnail scrubbing built by ffmpeg-ing the file. | **REFUSED by implication** (no ffmpeg, no transcoding) — but the prompt never says so, and scrub previews are a baseline expectation. **ABSENT — LOW/MEDIUM.** |
| 2.12 | **Media segments** (10.10+) — typed intervals `Intro`, `Outro`, `Recap`, `Preview`, `Commercial`, with begin/end timestamps, produced by plugins, consumed by clients as skip buttons ([media-segments](https://jellyfin.org/docs/general/server/metadata/media-segments)) | A typed-interval model over a single edition's timeline. | **ABSENT — MEDIUM.** Notably this is *structurally the same shape* as CanonCore's `edition_coverage` (a set of typed intervals over an edition) but for a different purpose; a builder reading the prompt would not know the table might serve both, and skip-intro is the single most-requested playback feature in this category. |
| 2.13 | **Segment types are extensible only by plugin; a `Chapter Segments Provider` derives segments from chapter names** | Deriving one metadata kind from another. | **ABSENT — LOW.** |

**Docs thin here:** the Metadata index page is ~15 lines and documents no refresh behaviour, no per-field precedence and no provider ordering — all of which exist in the UI. The NFO page's own tag list is prefaced "may not be exhaustive". `chapter-images` says settings live in "Libraries -> Metadata" but the Settings page (§4) does not document that panel.

## 3. Users, authentication and permissions

Sources: <https://jellyfin.org/docs/general/server/users/>,
<https://jellyfin.org/docs/general/server/users/adding-managing-users>.

CanonCore is deliberately single-user (`owners` = ONE row, no signup, no multi-tenancy, no
visibility system, `owner_id` retained for a later migration). Most of this section is therefore
correctly deferred. The items worth flagging are the ones that bite a **single-user** instance.

| # | Jellyfin feature | One line | CanonCore |
|---|---|---|---|
| 3.1 | **Local-only users; nothing sent remotely at login** | "Jellyfin users are entirely local and no information or metadata will ever be sent to remote servers during the login process." | **ADOPTED** — single password, no signup. |
| 3.2 | **Admin flag** (`allow this user to manage the server`) — binary, "full access to all pages and features" | There is no role model, just admin/not. | **DIVERGENT/deferred** — one owner. Note even Jellyfin never built roles. |
| 3.3 | **Per-user, per-library access** (`Enable access to all libraries` off → tick-list); **new libraries default to denied** for restricted users | Library-scoped ACL. | **REFUSED (deferred)** — "No visibility system… Add it when multi-user arrives." Note the default-deny-on-new-library rule is the non-obvious part, and it is the correct default. |
| 3.4 | **Per-user, per-device access** (`Enable access from all devices` off → new devices blocked until approved) | Device allowlist as a second axis. | **ABSENT — LOW** (multi-user only). |
| 3.5 | **Failed-login lockout** — configurable threshold; default **3 for non-admin, 5 for admin**; `0` = inherit, `-1` = disable; unlock is a manual admin action; lockout surfaces on the activity feed | Brute-force protection on the login form. | **ABSENT — HIGH.** CanonCore is one password with no signup, self-hosted and (per the networking docs) commonly exposed to the internet. A single password with no rate limit, no lockout and no backoff is the entire attack surface. The prompt specifies a Safe External Fetch boundary for *outbound* requests and nothing at all for *inbound* auth. |
| 3.6 | **Password reset to no-password** — admin can blank a password so the user logs in without one | Recovery path. | **ABSENT — MEDIUM.** With exactly one owner and one password there is no admin to reset it. A self-hosted product needs a documented "I lost the password" path (CLI reset against the DB is the usual answer). Nothing in the prompt. |
| 3.7 | **Pluggable authentication provider** (default, or LDAP via plugin; username must match LDAP UID including case) | Auth backend is swappable. | **ABSENT — LOW.** Single-user makes this moot for v1. |
| 3.8 | **Hide user from login screen** (all new users hidden by default); **disable user** kicks live connections immediately | Account visibility and immediate revocation. | **ABSENT — LOW/MEDIUM.** "Kicks existing connections immediately" implies a session-revocation mechanism (see §5 Devices) that CanonCore does not mention. |
| 3.9 | **`Allow remote connections`** per user — blocks logins originating outside the configured local subnets | Network-origin as an authorisation input. | **ABSENT — MEDIUM.** A LAN-only mode is a common and cheap safety valve for self-hosted software; the prompt says nothing about local vs remote request origin. |
| 3.10 | **Playback permissions** — allow playback at all; allow transcoding; allow remux-without-re-encode; **internet streaming bitrate limit (Mbps)** for out-of-network devices | Resource control per user. | **REFUSED** (no transcoding) except the bitrate cap. **ABSENT — LOW.** |
| 3.11 | **Media deletion permission**, all-libraries or per-library; **deletes from the filesystem**; if the server lacks write permission the item "will be removed temporarily but picked up on the next library scan" | Delete = unlink the file. | **DIVERGENT — important.** CanonCore's DELETE section is entirely about catalogue rows and placements and **never says whether Delete touches the file on disk**. Given "the scanner NEVER writes storage", the answer should be no — but then the Jellyfin failure mode described here (row deleted, file survives, next scan resurrects it) is *exactly* what CanonCore will do, and the prompt does not address resurrection at all. **ABSENT — HIGH: what stops a deleted item being re-created by the next scan.** |
| 3.12 | **Remote control of other users / of shared devices** | One session drives another's playback. | **ABSENT — LOW.** Multi-user. |
| 3.13 | **Download & sync permission** ("Syncing and Transcoding are currently not available") | Offline copies. | **ABSENT — LOW/MEDIUM.** Offline download is the top request for phone clients, and the prompt commits to a phone app. |
| 3.14 | **Parental control** — max allowed rating, block unrated items, block-by-tag, allow-by-tag, and an **access schedule** (login and playback only inside time windows) | Content filtering plus time-boxing. | **REFUSED (deferred with visibility).** But note the *inputs*: a content-rating field and tag-based filters. CanonCore has tags as `category` statements (fine) and **no content-rating field at all** (see 2.4). |
| 3.15 | **`Allow social media sharing`** — share a public URL to an item page | Per-user permission to publish a link. | **ABSENT — LOW.** CanonCore's public surface is a whole separate read-only demo instance. |

**Docs contradiction:** the Users overview says a locked-out user "will no longer be able to login
until the server administrator manually unlocks the account", while the detail page says unlocking is
done by unchecking `Disable this user` — i.e. lockout is implemented by flipping the disable flag,
which is not what the overview implies. Three settings on this page are documented as
"currently not available" (`Allow media conversion`, sync, transcoding-on-download).

## 4. Server settings, scheduled tasks, devices, Quick Connect, notifications

Sources: <https://jellyfin.org/docs/general/server/settings>,
`/server/tasks`, `/server/devices`, `/server/quick-connect`, `/server/notifications`.

| # | Jellyfin feature | One line | CanonCore |
|---|---|---|---|
| 4.1 | **Server name**, shown in client server-pickers | The instance has an identity separate from its URL. | **ABSENT — LOW/MEDIUM.** A phone/TV client that can hold several servers needs a name to show. The prompt commits to those clients. |
| 4.2 | **Login disclaimer** and **custom CSS** on the web UI | Per-instance branding/legal text. | **ABSENT — LOW.** |
| 4.3 | **Splash-screen image auto-generated from library content, visible pre-auth**, filtered to ≤PG-13 "but this depends on the content having accurate rating data" | An unauthenticated surface that leaks library contents. | Useful negative example: an unauthenticated page derived from private data, gated on a metadata field that may be missing. CanonCore's public read path "NAMES every field it emits", which is the right answer to exactly this. |
| 4.4 | **Scheduled tasks, each individually rescheduleable and manually runnable** ([tasks](https://jellyfin.org/docs/general/server/tasks)) | A cron surface in the admin UI. | **ABSENT — HIGH.** The prompt has a scanner, a projection rebuild, enrichment running "in the background", a six-month TMDB cache expiry and a review queue — four or five things that must run on a schedule — and specifies **no scheduler, no task list, no run history, no manual-trigger surface and no way to see whether a background job failed**. |
| 4.5 | **The default task list**: Scan Library · Download Missing Subtitles · Refresh Users · Extract Chapter Images · Extract Key Frames · Update Plugins · Optimize Database · Clear Log Folder · Clear Cache Folder · Clear Activity Logs · Clear Transcodes Folder · Clean up collections and playlists | The actual maintenance surface of a media server, enumerated. | Checklist of what a builder must invent. CanonCore analogues absent: log rotation, cache eviction, activity-log pruning, database optimise, orphan cleanup. **ABSENT — MEDIUM/HIGH each; see §7 and §8.** |
| 4.6 | **Data-loss warning:** if media is unavailable when `Clean up collections and playlists` runs (e.g. an unmounted network share) **"your playlists will be lost"** — and it runs at startup by default | A cleanup task that cannot distinguish "gone" from "not mounted yet". | **ABSENT — HIGH.** CanonCore's items survive without files, so the catalogue is safe, but nothing in the prompt says what the **scanner** does when a root is empty or unmounted, and its own storage section already warns that network mounts are unreliable. A scan of an unmounted root that marks every file missing is the same bug with a different blast radius. |
| 4.7 | **Plugins can register their own scheduled tasks** | Extensions get the same scheduler. | **N/A** — CanonCore providers are remote URLs and run no code. |
| 4.8 | **Devices list** — every device that has ever connected, the user registered to it, editable display name, removable (re-appears on reconnect) | Session/device inventory. | **ABSENT — MEDIUM.** With a phone app, a TV app and a web client all holding a session, an owner needs to see and revoke them. The prompt mentions "a single-password cookie session" once and nothing else about session lifetime, revocation or device identity. |
| 4.9 | **Quick Connect** — a 6-character code shown on a TV, entered on an already-authenticated device, authorises the TV without typing a password ([quick-connect](https://jellyfin.org/docs/general/server/quick-connect)) | Device-code auth flow for input-poor devices. | **ABSENT — HIGH (given the TV client).** The prompt commits to a native Swift tvOS app and never says how it authenticates. Typing a password on a tvOS remote is the known-bad experience Quick Connect exists to fix, and Jellyfin's own support matrix shows it is table stakes: 12 of 14 listed clients implement log-in via Quick Connect. |
| 4.10 | **Notifications are a plugin (Webhook)**, not core — per-notification-type toggles, optional per-user scoping, templates for popular messaging services ([notifications](https://jellyfin.org/docs/general/server/notifications)) | Server events pushed to Discord/Slack/etc. via user-authored templates. | **ABSENT — MEDIUM.** The prompt's review queue, "dropped at the door and counted" report, and failing provider calls all produce things the owner needs to be *told* about. There is no notification, email, webhook or even an in-app inbox specified — only "the owner is told", with no mechanism. |
| 4.11 | **Dashboard notifications by default** — an in-app activity/notification area | Baseline: events land somewhere in the UI even with no integration. | **ABSENT — MEDIUM.** Same gap as 4.10; this is the minimum version of it. |

**Docs very thin here:** the Settings page documents four cosmetic options and *none* of the
substantive dashboard settings — no library scan options, no metadata refresh options, no
`Libraries → Metadata` panel (which `chapter-images` explicitly refers readers to), no image
options, no playback settings. The Devices page admits it "is really only useful to see connected
devices". This is the largest doc/product mismatch in the whole site.

## 5. Plugin architecture and the plugin repository model

Sources: <https://jellyfin.org/docs/general/server/plugins/>,

## 10. The API, and the features Jellyfin ships but never documents

Source: the stable OpenAPI document at
<https://api.jellyfin.org/openapi/jellyfin-openapi-stable.json> (fetched 2026-09-06;
OpenAPI 3.0.4, **294 paths, 46 tags**), browsable at <https://api.jellyfin.org/>.

**Major docs failure, stated plainly as instructed:** three headline Jellyfin features —
**Collections, Playlists and SyncPlay** — have **no documentation page on jellyfin.org/docs at
all**. Grepping the entire docs source tree returns zero prose pages for any of them; "collection"
appears only in passing (a tasks entry, an NFO tag, a plugin blurb) and "syncplay" appears exactly
once, in a commented-out line of the Apache reverse-proxy config. They exist only in the API. The
same is true of the **library scan options** (§10.6), which are the single most consequential
configuration surface in the product.

# GAPS — ABSENT FROM CANONCORE

Everything rated **MEDIUM** or **HIGH** above, consolidated and ranked. "ABSENT" means the
CanonCore prompt says *nothing at all* — not that it decided against it. Since the prompt is the
only artefact a builder will have, each of these is something they will either invent from scratch
or never think of.

Ranked within each tier by how early the decision has to be made (earliest first), because the
prompt's own rule is that per-field provenance and the migration ladder cannot be retrofitted, and
several of these are in the same category.

## HIGH — a self-hosted media catalogue genuinely needs these

| Rank | Gap | Why it is HIGH | Ref |

| 1 | **Language on statements.** No `language` anywhere in the model. | Providers return titles, synopses and taglines per language; TMDB is language-parameterised; the demo franchise has different UK/US titles. ## Notable NON-gaps (where CanonCore is ahead, confirmed by the docs)

- **Show specials ordering.** Jellyfin needs three metadata fields (`airsbefore_season`, `airsafter_season`, `airsbefore_episode`) plus a display toggle to put one episode in two orderings. Placements do it natively. (1.16)
- **Collections have no reorder endpoint at all** in the API — proof that Jellyfin BoxSets are sets, not sequences. Playlists reorder by dense index (`Move/{newIndex}`), which is exactly the stale-key problem CanonCore's stable placement id avoids. (10.1, 10.2)
- **Search/apply split.** Jellyfin already has `RemoteSearch` and `RemoteSearch/Apply` as separate endpoints; the prompt's critique is of the merge policy, not the seam. (10.11)
- **`.nfo` cannot be disabled and always beats remote providers** — first-non-empty-wins with a hardcoded order, documented in Jellyfin's own words. (2.6)
- **Mixed library type "is broken and deprecated"** — the untyped library is the one Jellyfin could not make work, which supports refusing medium-typed groups. (1.3)
- **Emby→Jellyfin migration is "NOT SUPPORTED"** — direct evidence that refusing cross-instance import is sound. (6.7)
- **Guide data allows exactly one provider, "you currently cannot use both at the same time"** — the single-primary-source pattern at its most extreme. (9.2)
- **Live TV channel mapping is a compulsory manual reconciliation wizard** — the anti-pattern the prompt refuses, tolerable only at ~50 channels. (9.3)

## Corrections to claims in the CanonCore prompt

Small, and none of them changes a decision — but a builder who checks will find these.

1. **"In Jellyfin and Plex an item cannot exist without a file."** Jellyfin has documented **placeholders**: an empty `.disc` file creates a full library item with metadata and artwork, marked as a placeholder rather than playable, for movies and episodes. The file must exist but is empty and its contents are unused. The prompt's structural point survives (identity still comes from a path on disk), but the sentence as written is refutable in one page of the docs. — <https://jellyfin.org/docs/general/server/media/placeholders>
2. **"Jellyfin has a play count but no dates."** `UserItemDataDto` carries `LastPlayedDate` alongside `PlayCount`. It is one overwritten date, so the substantive claim — no history, re-watches unrecoverable — holds; "no dates" does not. — <https://api.jellyfin.org/openapi/jellyfin-openapi-stable.json>
3. **"Ordering lives in filenames"** is true of the scanner, but Jellyfin *does* ship one alternate-ordering mechanism: specials can be placed inline in an aired season via three NFO/metadata fields, appearing in both Specials and the target season. It is three fields, not a general construct, so reason #2 stands — but it is not "one ordering, full stop". — <https://jellyfin.org/docs/general/server/media/shows>

## Where Jellyfin's documentation is thin or self-contradictory

Recorded as instructed.

- **Collections, Playlists and SyncPlay have no documentation page whatsoever.** Three headline features; zero prose. They exist only in the OpenAPI document (3, 11 and 22 endpoints respectively). "syncplay" appears exactly once in the whole docs tree — in a commented-out line of the Apache reverse-proxy config.
- **`LibraryOptions` — ~40 per-library scan and metadata settings — is undocumented.** The Settings page covers four cosmetic options and none of the substantive dashboard settings. `chapter-images` tells readers to go to "Libraries → Metadata", a panel the docs never describe.
- **The Libraries page is five paragraphs** and documents none of the scan configuration.
- **`mixed-movies-and-shows` is a two-sentence stub** admitting the feature is broken.
- **`_video-header` contradicts itself**: `.iso` files "should work, but are not supported".
- **The Users overview and detail page disagree** about how a locked-out account is unlocked (manual unlock vs unchecking `Disable this user`).
- **Three user settings are documented as "currently not available"** (`Allow media conversion`, sync, download-with-transcoding).
- **The Devices page admits it "is really only useful to see connected devices"** and exposes one editable field.
- **The NFO tag list is prefaced "may not be exhaustive"**, and warns that when two tags map to the same internal field "the last of these tags in the file will have priority" — undefined-by-design precedence.
- **Metadata index page is ~15 lines** and covers no refresh behaviour, precedence or provider ordering.
- **Plugin catalogue version numbers "may not be accurate."**
- The database tuning options are explicitly **"not part of the stable API… Jellyfin does not migrate the values you set."**
