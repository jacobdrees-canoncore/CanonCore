## Decisions

### What the design rests on

- **untitled.stream is the design foundation** (ADR 0020). Its look and its structure lead. The
  frosted-folder portfolio contributes one signature component: the folder. A folder is a
  presentation that any grouping may use, never a domain term. (Amended 2 Oct, ADR 0023: where
  untitled's look and Arc's disagree, which leads waits on CC-38's Look switch.)
- **Outside code is used freely, but ships only under a licence the AGPL can carry** (ADR 0019).
  fayazara agreed on 30 Sep to add a licence to the portfolio repo; its code ships in CanonCore
  once a LICENSE file is in that repo. Apple's AML sample licence is accepted like MIT, with
  Apple's notice kept. Apple's photographs, videos and artwork never ship.
- **The web client is Tailwind 4, the shadcn registry and Motion**, with a DESIGN.md holding the
  tokens and `@shadcn/lint` enforcing them (ADR 0021). Arc and ObsidianUI are evaluated as
  registry sources inside the prototype. (Superseded 2 Oct by ADR 0023: the web client uses Arc
  as it ships, shadcn on Radix, DESIGN.md as a mirror of Arc's tokens, no `@shadcn/lint`;
  ObsidianUI and uselayouts are dropped.)
- **Five clients:** the web, iPhone, iPad (with an adaptive layout of its own), Mac and Apple TV
  (ADR 0009). visionOS and watchOS are not clients.
- **The whole brand arrives at public release** (CC-8): name mark, type, palette and mascot.
  Until then the prototype and the product use a neutral face and palette. Nothing drawn by
  untitled, and not its fonts, goes into CanonCore. (Amended 2 Oct, ADR 0023: on the web the
  type is Arc's, Geist and Inter at 400 and 500, and the neutral face is Arc's tokens.)
- **Nothing waits for TMDB.** CC-14 stays open. The Admin's own key stands until a written yes,
  as CC-2 already says.
- **TARDIS Guide is used, as a private install.** Shaun Robinson's thread of 28 Sep (sets, playlists
  and prerequisites added to TARDIS Guide's API, and beta API access given to the Owner's Bronze
  Patron account after an email describing CanonCore) is, in the Owner's reading, TARDIS Guide's
  yes to CanonCore using its data (decided 30 Sep, after the verification). Its API is open only to
  Patrons, so it stays a private install by URL used with each Admin's own Patron key: the Store
  carries no paid Provider (ADR 0002) and CanonCore ships no key (ADR 0003). The snapshot fetches its
  sets, playlists and Prerequisites through its own ticket. The Tardis Fandom Timelines stay the
  first Ordering source for Doctor Who; TARDIS Guide adds sets, guides and playlists beside them.
  `GLOSSARY.md` gains Prerequisite for what it calls prerequisites.
- **The server targets Node 26**, LTS from 28 Oct 2026 (ADR 0016).

### The recreations

A recreation is a standalone replica of a real product, built to study its design. It is never
CanonCore. Each lives in its own repository under `~/canoncore/`, with a private remote in the
`jacobdrees-canoncore` GitHub organisation (ADR 0022). Replicas are named `<name>-replica`, with raw
recordings and captures kept out of git beside them in `<name>-replica-data`: `untitled-replica`,
`untitled-app-replica` and `brink-replica` (`md-vinyl-replica`, `america-gov-replica` and
`tv-app-replica` were dropped 3 Oct 2026). The snapshot, the folder component and the prototype keep their own names
(`prototype-snapshot`, `folder-component`, `design-prototype`). (Decided 30 Sep, after the
verification.) (Amended 6 Oct 2026: files taken from the originals, their fonts, icons, Rive
files, shaders and media, are committed to each replica's own repository, the untitled web replica's
site images and IBM Plex Mono included; only raw recordings and captures stay out of git. The makers
permitted extraction. The repositories stay private, and nothing of theirs reaches CanonCore, ADR
0020.)

### The design prototype

- **Throwaway.** It lives in `~/canoncore/design-prototype`, private, never in CanonCore's public
  repository (ADR 0022). What reaches CanonCore's main branch is DESIGN.md, the verdict on each
  spec, and the picked variants described in words and tokens. Project 1 builds its components
  fresh, test-first, from those.
- **Two specs, web and Apple.** The Apple half reuses the web half's shell structure and
  DESIGN.md tokens, so the structure is decided once, on the web.
- **One shell holds every project's screens**, so the product is judged whole. Variants go first
  to the shell and project 1's screens (layer 1). Later projects' screens stay single drafts until
  just before their own spec (layer 2).
- **Variants follow D-66:** Matt Pocock's `prototype` UI sub-shape B; on the web, `?variant=`
  with a floating switcher; in SwiftUI, an equivalent picker hidden in release builds; 3
  variants by default, at most 5. D-66's "real data (the library-model fetch)" is replaced by the
  data snapshot below. The web prototype also shows its variants in Storybook, beside the real
  routes.
- **The data is a real snapshot plus hand-made edge cases**, covering the data of all ten
  projects: Items in every medium and hierarchy, Editions and Versions, Entities and Credits,
  Orderings and Franchises, Music cues, books, comics, Filming sites, Profiles, and the Store's
  Provider listings. Real titles and artwork come from several Providers, fetched with Jacob's own
  keys, at a scale of thousands of Items. The hand-made additions cover what real data rarely
  shows: Missing Items, Offline Versions, Unmatched files, Repeats, absent art and very long
  titles. The 600-Placement Timeline, the Eleventh Doctor's, is fetched from Tardis Fandom, with
  only the shapes it lacks hand-made. Where no real source exists yet (Filming sites, for one), a
  hand-made example shows the idea. Both prototypes read the same file. It is not Doctor Who alone
  (ADR 0008). Comics come from Metron and the Grand Comics Database. Comic Vine is neither used nor
  listed in the Store, because its terms forbid editing or reshaping its data, which every
  Provider does (decided 30 Sep, after the second verification).
- **The web half starts when** untitled web is done (CC-151, CC-15's round-2 audit), the
  snapshot release its README pins exists (v2.0.1) and the folder's web gallery works (CC-50). **The Apple
  half starts when** the whole web prototype is done (CC-38, not only its shell), the untitled app
  replica is done and accepted (CC-36, iPhone and Mac), the folder's SwiftUI gallery works (CC-57)
  and the snapshot release its README pins exists (v2.0.1).
  (Amended 6 Oct 2026: "accepted" means the untitled app replica's audit has reached its clean round
  with the Owner's walk on the phone and the Mac, and the Apple half also waits for Brink's look,
  CC-33. The Apple half is built from the web prototype, the folder, Apple's sample code, snapshot
  v2.0.1, the untitled web replica, the untitled app replica, and Brink both as its look (recorded on
  the phone, its cards) and as Extractor's files, and the reference screenshots in

  decided at its grill. It may use untitled's and Brink's fonts and icons inside the private

  (Amended 3 Oct 2026: the prototypes pin v2.0.1, the release the snapshot's README pins, in place of

  (Amended 3 Oct 2026: the folder's real-remote proof on Apple TV, CC-62, is canceled, so the Apple

  (Amended 8 Oct 2026, superseding the milestone gates above: the Design references specs run one

## Order

The Design references specs are built one at a time, in the order the Owner set on 8 Oct 2026:

1. the folder component (CC-37)
2. the web prototype (CC-38)
3. Brink's look (CC-33)
4. the untitled app replica (CC-36)
5. the Apple prototype (CC-39)

Each finishes, its audit at its clean round with the Owner's walk, before the next one's first
ticket starts. The board enforces it: each audit ticket blocks the next spec's first ticket (the
folder's audit CC-140 blocks CC-193, the web prototype's CC-206 blocks CC-207, Brink's CC-217
blocks CC-218, and the untitled replica's CC-242 blocks CC-39). An audit ticket stays open until the
Owner sets it Done after the walk, so each edge releases at the clean round. Inside the current
spec, every unblocked ticket runs in parallel within the ceiling in `docs/agents/dispatching.md`.
Main plans the next spec (its fixes, check rounds and `/to-tickets`) alongside the current build,
starting with the Apple prototype, which has no tickets yet. Main dispatches the whole Design
references project, so one session sees every agent slot, the phone and Jacob's sign-ins.

## Driving the iPhone

The route is `driving-the-iphone.md`'s first: WebDriverAgent (signed with Jacob's Apple
Developer team) for taps, swipes, typing and the accessibility tree, and `xcrun devicectl` for
screenshots and screen recordings. Its first measurement is a five-second recording checked with
`ffprobe` for frame rate. Enable UI Automation is on, and Brink, MD Vinyl and [untitled] are
installed ([untitled] measured in `driving-the-iphone.md`; the other two installed by Jacob in the grill).

During a session the agent:

- installs WebDriverAgent once (Jacob approves it on the phone)
- opens only the app being studied, and never buys, posts, follows, shares, uploads, deletes or
  changes settings; in [untitled] it only views, except as below
- may switch Appearance (light or dark) and fake the status bar for a recording, and restores both
  before the session ends; whether `devicectl` can set Appearance on a real device is checked in
  the first phone ticket
- in [untitled], may switch the app's own theme setting on account A for a recording and restores it
  before the session ends; that setting is account-wide, so never while the web replica's capture
  is running
- never answers a permission prompt with Allow: it declines, or stops and tells Jacob
- keeps raw recordings out of git, in the replica's `-data` folder; files taken from the original
  (fonts, icons, Rive files, shaders, media) go into the replica's git (amended 6 Oct 2026)
- records the original twice, and a replica's transition passes when it falls within the spread
  between the two recordings, never tighter than one frame (amended 6 Oct 2026: the untitled app
  replica, CC-36, keeps one comparison seam, the accessibility tree, pixels at 0.1, and motion, run on
  the iPhone and the Mac captures, the Mac's tolerance measured on the Mac; untitled's originals and
  replicas are recorded on the same macOS build. The folder keeps its macOS 26.6 recording, re-recorded
  on macOS 27 only if a folder comparison fails after the update; amended 8 Oct 2026: the update is
  done, so every folder comparison from now on, the web gallery's included, runs on macOS 27.0.1)
- tells Jacob before it starts and when it is done; the phone stays unlocked, on charge, with
  Auto-Lock set to Never, and untouched
